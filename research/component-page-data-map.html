The contract, in four terms

Each view is the same query at two altitudes. The interactive surface adds a fourth term — state — so the agent can read back what the user is looking at.

Tool
What the model may call. Typed params, no free-text SQL.
Chart
A deterministic render of the returned rows. App-owned marks.
Page route
The same query, full and paginated — the authoritative records.
State
Interactive only. Selection = deep-link params, stated once.
The deep link is the tool call serialized. Page and chat answer cannot disagree, because the link is derived from the call, never hand-authored.
The model never emits a number. It narrates figures the tool returned and the chart drew. Fabricated numbers become structurally impossible, not prompt-discouraged.

05

Deliberately unsupported

Each is a data gap, not a backlog item. Bounded tools refuse these for free — which is the correct answer, not a limitation to design around.

Compensation 1.7%
Structured pay on 134 of 8,107 postings, effectively Lever boards only. Any comp chart renders noise.
Geography ~0%
City arrays effectively empty; only free-text location strings exist. Location answers would be parsed on the fly and wrong.
Remote vs. onsite 33%
Workplace type present on a third of postings, and which platforms report it is non-random. Describes ATS habits, not the market.
Whole-market claims 119 co.
A hand-picked, AI-heavy set. Sound for "this niche," misleading as "tech hiring."
Causality & advice n/a
Why a company hires, and whether a user is qualified, are both outside what postings support.
06

Decisions to log

Open threads this map surfaces. Numbered because they need resolving in order — the first two gate what gets drafted next.

Model-API dependency is accepted

The chat surface is the project's first runtime model-API call, via OpenRouter. Backend data-building stays on the subscription-authenticated CLI path (batch-enrich), so the API cost is bounded to per-question analysis, not bulk enrichment. This reverses the implicit "no runtime API" posture and should be written down as a decision, not left as an implication.

Decided

First interactive component

Recommend leading with Movers or Demand Trend rather than Skill Overlap. Both are full-corpus, both exercise the chart primitives against real scale/path geometry, and Movers is already the intended cold-start seed. Skill Overlap sits on the 35% classified dimension and its set-intersection form is the weakest exerciser of the chart layer.

Open

Give the epic its page-route leg

The Conversational Analysis Surface epic covers transport, registry, state, and the chat frame, but no page-route item — the third term of the contract. This map is that leg; fold a page item per component into the roadmap, with /postings as the shared terminus.

Roadmap

Un-defer two non-goals

Committing to an AI-first UI un-defers Next.js product screens and the agent UI, both currently listed as non-goals. Update project.md when the epic is committed so the docs don't contradict the plan.

Docs

The roadmap cites research/… as a bare path; from agent-context/plans/ that resolves to a directory that doesn't exist. The files live at repo root — use ../../research/… as project.md already does.
